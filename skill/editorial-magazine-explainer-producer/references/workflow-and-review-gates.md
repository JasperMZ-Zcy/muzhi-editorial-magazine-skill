# 启动、交付物与审核闸门

## 启动扫描

获得用户执行授权后，先判断运行模式：

- `workspace`：读取该工作区要求的入口、协作手册、协作总览、当前设备进度页、决策日志、最新每日总结和会话交接；再读取当前项目状态、最后一个已批准检查点和最近一条同产线已验收项目。若工作区有 `AGENTS.md`，先遵守其中规则。
- `standalone`：读取本 Skill、用户提供的音频/字幕/文案/素材和当前项目记录；若用户自己的项目存在 `AGENTS.md`，先遵守。不得因为缺少牧之远见的私有知识库而阻塞制作。

启动输出必须明确：

- 当前事实源：真实音频、已确认文案、SRT、用户素材；
- 当前母钟、字幕、声音档案和项目状态；
- 已批准且禁止重做的内容；
- 第一个未完成 Gate；
- 本轮预期交付物、人工审核点、供应商和费用；
- 发布是否在授权范围内。

历史文件名、聊天记忆或用户口头简称不是事实源。使用项目标记、哈希、QA 和明确批准记录判断。

## Gate 0：授权与能力预检

1. 渐进澄清到至少 95% 理解把握，每次只问一个问题。
2. 完整复述目标、保留项、可替换项、视觉标准、声音、交付形式和验收方式。
3. 说明计划使用的本地工具、生成供应商、可能成本和用户需要手动完成的环节。
4. 等待明确“同意 / 开始 / 执行”。
5. 检查所需音视频、转写、生图、Flow、渲染、抽帧和 QA 能力可用。

能力或授权不完整时 Gate 0 关闭。

## Gate 1：真实音频、字幕与母钟

### 输入保存

- 原始录音、SRT、定稿文案和用户素材只安全复制，不覆盖原件。
- 记录来源路径、时长、采样率、声道、哈希和最后一句。
- 用户临时改词以录音实际语义为准；文案用来发现错听、同音错字和断句问题。

### 文本处理

- 允许修正：明确错字、同音词、断句、无意义口误重复。
- 禁止擅改：观点、例子、结论、态度、承诺和事实强度。
- SRT 锁定后记录条数、首尾时间、末句和哈希。
- 词级定位只服务动作；不能替代批准的 SRT 文本。

### Gate 1 交付物

- 校正稿或差异说明；
- 最终 SRT；
- 母钟探测报告；
- 词级锚点；
- 镜头结构和每镜唯一主命题；
- 必须锁定的内容、音频、字幕和资产。

对于“真实录音＋已确认文案”的入口，Gate 1 默认内部完成，不拿纯文字审核打断用户。只有出现改变意思、时长、产线路由或重要例子的冲突时才停止确认。

## Gate 2：全片逐镜方案审核

每镜 TXT 合同必须包含：

- 镜号、精确起止时间、完整口播；
- 唯一主命题、主语、动作、受力对象、转折和结果；
- 镜头家族及选择理由；
- 稳定主构图持续时间和短于 1.5 秒的例外理由；
- 分阶段 `sceneStart`、`actionCue`、`textCue`；
- 独立图层、运动走廊、空间归属和六阶段生命周期；
- 解释文字、形式、职责和与字幕的差异；
- 气泡、票据、输入框、选项等语义容器的本地文字；
- 字幕、高亮、单行策略和最长句边界风险；
- 与前后镜头的接管与退场；
- 所需资产、供应商、禁止捷径和 QA 点。

每镜同时交付一张审核图：

- 组件镜头：横向多阶段关键帧，至少显示进入、核心、收束；
- Flow 镜头：无字准备态参考图和镜头方案；
- 整幅插画：最终构图和轻动职责；
- 所有图中显示正式字幕区、解释区和组件区，但不保留内部生产标记作为正式画面元素。

全片还必须交付：

- 全镜关键帧总览；
- 主构图密度/节奏表；
- 解释文字形式分布；
- 空白语义容器审计；
- 图层退出与相邻镜头重复隐喻审计；
- Flow 镜头清单；
- Gate 2 检查清单。

把上述文件全部登记到 `editorial-gate2-manifest.json`：每镜合同、TXT、关键帧和组件图层计划均记录真实路径与 SHA-256；全片七项总览/审计同样记录路径与 SHA-256。清单中的镜头集合必须与项目合同完全一致。Gate 2 批准还必须保存批准人、用户“整套通过”的原话和时间，不能只把状态字符串改成 `approved`。

所有文件单层平铺到一个审核目录。交付后停止等待明确的整套批准。部分镜头或风格方向通过，不等于 Gate 2 通过。

## Gate 2.5：Flow 手动生成包

只有 Gate 2 明确整套通过后才创建。目录只放批准的 Flow 镜头：

- 一镜一张无字准备态参考图；
- 一镜一份完整生产级 TXT；
- 镜号、对应口播、建议时长、动作锚点和回收路径；
- 全局风格、无文字、无水印、无字幕、无声音的统一禁止项。

提示词必须写清首帧、分段动作、人物/物件、运镜、构图、材质、景深、结束状态和禁止项。不得只写几句方向描述。

交付用户后停止，等待手动生成结果。不要把非 Flow 参考图、未批准旧稿或正式合成文件混入。

## Gate 2.6：Flow 回收验收

- 按内容检查实际镜头，不信任文件名。
- 保存 raw 原件和真实映射；不覆盖用户文件。
- 检查首、中、尾、手部、人物一致性、动作、伪文字、水印、Logo 和构图漂移。
- 移除所有源音轨，标准化到批准规格。
- 不拉伸已批准动作；按动作发生帧对齐 `actionCue`。
- 失败镜头单独退回，不重做已通过镜头。

## Gate 3：正式母版

Gate 3 包必须包含：

- 正式 1080×1920、30fps 母版或项目批准规格；
- 技术、声音、视觉和连续区段 QA；
- 全片语义阶段总览；
- 最长字幕边界总览；
- 返工锁定项哈希对比；
- 版本说明、回退版本和审核重点；
- 桌面审核副本和 SHA-256 一致性记录。

Gate 3 的 QA 清单必须绑定真实母版和桌面副本，重算文件哈希，并核对分辨率、帧率、时长、帧数、黑帧、异常静音、LUFS、LRA、真峰值、最小信息字号、最小解释字号和不可读边角小字数量。布尔声明不能替代实测值。

交付后停止。自动 QA 通过不等于用户观看通过。

## Gate 4：发布与数据闭环

成片通过后，发布仍是单独授权。用户自己发布时，只在用户明确确认平台完成后登记状态；需要平台操作时，登录、上传、发布每个实质动作都必须在批准范围内。

工作区模式登记每个平台：原生作品 ID、可用链接、发布时间、工作台内容 ID 和状态，随后设置 24h、72h、7d 数据节点。独立模式把相同信息记录在项目本地发布清单中。公开监控没有单条链接时使用原生 ID；用户已确认发布但细节尚未补齐时，明确写“已发布，平台细节待补”，不伪造 URL、时间或 ID。

## Gate 状态词

只使用真实状态：

- `not_started`
- `in_progress`
- `waiting_user_review`
- `approved`
- `rejected`
- `published`
- `tracking`

不得把“已生成审核包”写成“已通过”，不得把“用户正在发布”写成“已发布”。
