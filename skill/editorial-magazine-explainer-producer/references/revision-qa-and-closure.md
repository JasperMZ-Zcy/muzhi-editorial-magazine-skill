# 返工锁定、QA、版本与收束合同

## 返工前先建锁定矩阵

每次新版本开始前必须创建 `editorial-revision-lock-vN.json`，包括：

- 基于哪个已验收版本；
- 完整回退版本路径；
- 本轮唯一允许修改项；
- 明确禁止修改项；
- 锁定文件、音视频流、字幕和时间线指纹；
- 预期变化的 QA；
- 用户原话和批准时间。

常见锁定对象：

- 母钟、字幕正文、字幕时码；
- 旁白母带及样本数；
- 背景音乐和混音参数；
- Flow 源文件、播放速度、动作顺序、裁切和绝对位置；
- 代码时间线、镜头边界和关键动作锚点；
- 已通过的组件、解释文字、语义容器和版式。

返工锁必须按 `audio / captions / timeline / flow / bgm / components / typography` 七个机器域逐一声明：不适用、允许修改或锁定三者只能选一。锁定域必须列出实际文件和 manifest；正式校验会读取当前版本正在使用的路径并重算 SHA-256，不能只引用未触碰的旧回退版来证明新版本没变。Flow 锁定至少覆盖 raw/标准化文件、速度、裁切窗口、绝对时码、动作顺序和 placement manifest。

当 `components` 或 `typography` 允许修改时，锁定文件必须追加 `visual_change_contract`：

- `flow_policy`：是否完全锁定，以及锁定的画幅、裁切、速度、动作和绝对时码；
- `local_component_scale_percent`：默认目标约 8%–12%，逐镜允许值和例外理由；
- `full_illustration_inner_scale_percent`：默认约 4%–6%，并声明不得越过原边框；
- `caption_centerward_move`：字幕朝中心安全区移动的目标与逐镜避让范围；
- `caption_contrast_strategy`：最终字体、描边、投影/底衬、关键词色和最差背景检查方式；
- `main_visual_protection`：不可遮挡的人物、动作、结果状态和解释文字。

当字幕外观允许修改时，还必须记录上一批准版的逐条字号/位置基线、本轮最小字号增量、零增量或反向避让的批准理由，并额外锁定解释文字正文/形式/时码；不能用 `typography` 域的宽泛授权顺手修改解释文字。

只准改本轮列出的内容。发现必须扩大范围时，先停下向用户说明并重新确认。

## 版本策略

- 不覆盖已验收版本；新建 vN。
- 至少保留一个完整回退版：源码、正式资产、人声、音乐、母版、QA 和审核包。
- 更早版本至少保留最终 MP4 和小型记录，除非用户另有要求。
- 每版写清修改边界、锁定项、输出哈希和审核重点。

## 技术 QA

必须记录：

- 类型检查/构建检查；
- 视频尺寸、帧率、帧数、时长和编码；
- 音频编码、采样率和声道；
- 完整解码错误数为 0；
- 黑帧检测；
- 异常静音检测；
- 综合响度、LRA、真峰值；
- Flow 源音轨为 0；
- 缺失/陈旧资产为 0；
- 末句和最后一帧无抖动、重复或截断。

阈值在项目合同中声明。短片可使用约 0.2–0.3 秒黑帧阈值、0.7–2 秒异常静音阈值作为起点，但必须结合片尾/气口做人工解释。

## 锁定项 QA

返工后比对：

- 音频样本数、时长和 SHA-256；
- SRT/字幕 JSON 条数、正文、首尾时码和哈希；
- 时间线和关键代码文件哈希；
- Flow 文件哈希、无音轨、速度和时间位置；
- 配乐文件、处理参数和混音结果；
- 用户指定保持不动的任何资产。

不一致必须为 0，除非锁定合同明确允许。

## 视觉 QA

100% 检查：

- 每个组件镜头的每个语义阶段；
- 每个 Flow 和整幅插画镜头；
- 每个本地组件镜头的基线比例、最终比例、中部集中、安全边距和构图完整性；
- Flow 锁定画幅/裁切/速度/动作/绝对时码与整幅插画原边框内缩放；
- 解释文字形式、职责、可读性和退出；
- 所有承担语义的气泡/票据/输入框/卡片；
- 最长至少 5 条字幕的最终编码边界；
- 字幕最终字号、中心方向位移、最差背景对比、风格一致性和主视觉避让；
- 生产标记、小字、生成文字、水印、Logo、二维码；
- 上一主层退出和下一主层接管；
- 所有发生过修改的连续关键区段；
- 前 15 秒与信息密集段的真实观看节奏。

静态中点总览不能替代进入/核心/收束检查，也不能替代连续观看。

Gate 3 的机器 QA 必须记录两个独立审计对象：

1. `asset_class_scale_audit`：Flow 应比对数/实际比对数、本地组件应审核数/实际审核数、整幅插画应审核数/实际审核数、例外记录、边框违规数、裁切数、构图破坏数；所有对象必须覆盖，违规计数必须为 0。
2. `caption_visual_hierarchy_audit`：上一版基线、本轮最小字号增量、中心方向位移范围、例外记录、对比策略、最差抽帧对比、保护区证据、单行溢出数、安全区违规数、主视觉/解释文字遮挡数；违规计数必须为 0。

逐字幕证据清单的每条 `records[]` 必须至少包含 `cue_id`、`shot_id`、`baseline_font_px`、`final_font_px`、`required_increase_px`、`baseline_x_px`、`baseline_y_px`、`final_x_px`、`final_y_px`、`centerward_offset_px`，以及单行、溢出、安全区、主视觉和解释文字五项通过标记。坐标以最终编码画面的字幕中心锚点为准；校验器会根据画面中心重新计算基线与最终坐标的距离差，填报的 `centerward_offset_px` 必须与计算结果在 0.5px 容差内一致。零位移或反向避让必须逐条附批准原因和批准时间。

对比度必须使用二选一的明确事实：`contrast_ratio_measured=true` 时实测最差值不得低于 4.5；无法可靠测量时设为 `false`、数值留空，并用双边缘/局部底衬＋人工最差帧审计替代。禁止填 `0` 冒充测量结果。

## 全片观看

自动 QA、抽帧 QA 后，从编码后的最终 MP4 从头到尾完整观看一次。记录观看人、时间、文件哈希和发现。未完整观看不得进入 Gate 3。

## 桌面审核交付

项目母版和关键审核材料保留在正式目录，同时复制到：

`<DESKTOP_REVIEW_ROOT>`

要求：

- 复制，不移动；
- 清晰中文主题、产物类型和版本号；
- 不夹带损坏、过期或未完成文件；
- 逐文件 SHA-256 核对，差异数必须为 0。

## 存储清理

清理是独立的破坏性动作，必须有用户授权。执行前：

1. 列出永久保留、完整回退、仅保留母版和待删除范围；
2. 解析并验证每个绝对目标在项目/明确桌面审核目录内；
3. 只删除可再生成且用户批准的中间抽帧、低清预览、临时混音、旧审核副本等；
4. 不删除源素材、批准资产、最终母版、正式声音、QA、源码和回退版；
5. 删除后记录文件数、字节数、残留数和保留母版哈希。

## 项目收束

成片通过后同步：

- `project.json` 状态、最终路径、版本、哈希、回退版和 Gate 3 时间；
- 工作台内容阶段；
- 当前设备进度页；
- 决策日志、每日总结和会话交接；
- 经过验证且可复用的知识库经验。

## 发布闭环

发布是 Gate 4，不由成片批准自动触发。

- 用户手动发布：等待用户明确确认每个平台完成；
- 代操作发布：必须另有明确授权；
- 每个平台记录原生 ID、真实 URL（若有）、发布时间和工作台记录；
- 状态从 `waiting` → `published` → `tracking` 逐步更新；
- 启动 24h、72h、7d 数据节点；
- 无公开链接时记录原生 ID 与原因，不编造链接。

## Gate 3/4 一票否决

- 自动 QA 通过就宣称用户已验收；
- 没有回退版就覆盖旧版；
- 禁改项哈希漂移；
- 只看总览、不看连续区段和完整成片；
- 桌面副本与工程母版哈希不一致；
- 未授权删除中间产物；
- 把“正在发布”写成“已发布”；
- 没有平台原生 ID/事实依据却宣称发布完成；
- 成片批准后擅自登录、上传或发布。
