# Editorial Magazine Explainer Producer

面向教育培训赛道的知识口播视频制作 Skill。把口播中的对象、数字、步骤、因果和结论转成稳定可读的杂志插画语义镜头，不按字幕逐句机械配图。

把本 Skill 当成该产线的执行控制器，而不是建议清单。任何硬 Gate、锁定项或一票否决未满足时，停止推进并说明缺口；不得用“先做出来再说”绕过。

固定规程优先级不可颠倒：`不可变生产核心 → 项目风格 → 用户新增加法要求 → 本轮返工范围`。新增风格或单条反馈只能锦上添花，不得削弱母钟、Gate 2 真暂停、语义动画、图层退出、字幕可读、语音优先配乐、证据 QA 和发布另授权。

工作区模式可继续使用正式产线与样式：

- `<OPENMONTAGE_ROOT>\pipeline_defs\editorial-magazine-explainer.yaml`
- `<OPENMONTAGE_ROOT>\styles\editorial-magazine-explainer-v2.yaml`

本产线独立于 `$vox-collage-producer`。用户指定杂志插画产线时，不得自动改走 VOX，也不得退回通用动效模板。

独立模式不要求存在 OpenMontage；使用本 Skill 自带的合同、参考资料和校验器。

## 路径解析（跨电脑必须先做）

本 Skill 不得假设用户名、盘符或固定工作区位置。执行任何项目动作前，先解析以下运行变量：

1. `<SKILL_ROOT>`：当前 `SKILL.md` 所在目录；
2. 优先读取 `<SKILL_ROOT>\config\local.json`，识别 `mode=workspace` 或 `mode=standalone`；
3. 若没有本机配置，则读取环境变量 `MUZHI_WORKSPACE_ROOT`；
4. 再尝试从当前工作目录及其父目录寻找同时包含 `OpenMontage` 与 `AI_START_HERE.md` 的工作区；
5. 若没有完整工作区，进入独立模式：把用户指定的项目目录作为 `<PROJECT_ROOT>`，只使用本 Skill 自带资源，不要求补装牧之远见私有知识库。

工作区模式解析结果包含：

- `<WORKSPACE_ROOT>`：主工作区；
- `<OPENMONTAGE_ROOT>`：通常为 `<WORKSPACE_ROOT>\OpenMontage`；
- `<KNOWLEDGE_BASE_ROOT>`：通常为 `<OPENMONTAGE_ROOT>\创业知识库`；
- `<DESKTOP_REVIEW_ROOT>`：本机配置的审核交付目录。

独立模式只要求：

- `<PROJECT_ROOT>`：用户明确指定或批准创建的项目目录；
- `<DESKTOP_REVIEW_ROOT>`：当前系统桌面下的 `Editorial-Magazine-Review`，或用户指定的审核目录；
- `<SKILL_ROOT>`：合同、参考资料与校验器的来源。

仓库中的 `__FILL_WORKSPACE_ROOT__`、`__FILL_OPENMONTAGE_ROOT__`、`__FILL_KNOWLEDGE_BASE_ROOT__`、`__FILL_DESKTOP_REVIEW_ROOT__` 都是模板占位符，不是可直接使用的路径。创建项目合同时必须替换成已解析的真实绝对路径。安装器只保存本机配置，不把本机路径提交回 GitHub。

## 0. 执行授权

若项目目录或其父级存在 `AGENTS.md`，先读取并遵守。无论使用哪种模式，都先渐进澄清、完整复述目标、解释执行步骤与审核方式，等待用户明确回复“同意 / 开始 / 执行”。授权前不读取资产、不调用生成、不修改、不渲染、不发布。

只有执行范围、内容、审美、声音、供应商、费用、时长、发布权限都达到至少 95% 清晰度后才提交执行方案。每次只问一个问题。已授权范围内正常推进；发生实质变化时重新确认。

## 1. 启动必读与续做路由

获得执行授权后，按模式读取：

1. **工作区模式：**工作区入口、协作总览、当前工作人员进度页、决策日志、最新每日总结、知识库 V1—V8 复盘和 V2.0 正式产线；
2. **独立模式：**本 Skill 的详细合同、用户提供的品牌规范、口播、SRT、文案、项目说明和现有资产；不得寻找或假设牧之远见私有文件；
3. 两种模式都读取最近一条可访问、已获授权的同产线项目及其最终 QA、返工记录和锁定合同；没有案例时使用 `references/validated-case-and-qa.md`；
4. 续做项目时读取当前项目的合同、决策日志、交接文件、最新审核状态和资产清单。

不得仅凭当前对话重建已批准的镜头、Flow、字幕、音频或版式。续做时从第一个未完成 Gate 开始。

入口路由：

- **真实录音＋已确认文案：**真实录音是唯一事实源和母钟；文案只用于核对语义、错字、同音词和断句。
- **真实录音＋SRT：**SRT 是字幕正文基准；词级对齐只服务动画锚点，不擅改字幕措辞。
- **只有定稿文案：**只做临时规划时码；录音到位后必须重建字幕与动作锚点。
- **只有想法：**先调用 `$video-spec-builder` 完成导演式澄清和口播定稿，再返回本 Skill。
- **既有项目：**先检查批准版本、锁定指纹、当前 Gate 和待办；不重复生产已通过内容。

详细启动、交付物和 Gate 合同见 [workflow-and-review-gates.md](references/workflow-and-review-gates.md)。

## 2. 建立机器可检验的项目合同

在项目 `artifacts/` 下从模板创建：

- `editorial-project-contract.json`：母钟、字幕、镜头、Gate、Flow 和声音合同；
- `editorial-gate2-manifest.json`：逐镜合同/TXT/关键帧、全片总览、语义容器原生文字与构图适配审计的路径、真实哈希及整套批准证据；
- 每次返工创建 `editorial-revision-lock-vN.json`：只准改什么、绝对不能改什么、回退版本和锁定指纹；
- Gate 3 创建 `editorial-qa-manifest-vN.json`：技术、声音、视觉、全片观看和桌面哈希结果。

模板位于本 Skill 的 `assets/templates/`。逐镜模板与项目合同中的 `shots[]` 使用同一结构。正式推进前运行：

```powershell
python "<SKILL_ROOT>\scripts\validate_editorial_project.py" --project-contract <项目合同>
```

逐镜和 Gate 2 分别使用 `--shot-contract`、`--gate2-manifest`；返工或 Gate 3 追加 `--revision-lock`、`--qa-manifest`。正式 Gate 校验默认读取真实文件并重算哈希；`--skip-file-verification` 只供草拟结构，永远不能用来解锁生产。校验失败即 Gate 关闭。

新项目或任何返工还必须从 `production-enforcement.template.json` 创建 `production-enforcement.json`，并运行：

```powershell
python "<SKILL_ROOT>\scripts\validate_production_enforcement.py" --manifest <PROJECT_ROOT>\artifacts\production-enforcement.json
```

正式生产只接受 schema 2.0 及以上；旧 schema 只供历史读取，不能解锁生产。四层优先级、逐镜语义/时序/生命周期/布局、三轨声音、证据文件和 18 项负向失败规则见 [production-enforcement-and-release.md](references/production-enforcement-and-release.md)。

## 3. 母钟与字幕先锁定

1. 安全复制原始录音、定稿文案、SRT 和用户素材；保留原件。
2. 复核录音时长、采样率、声道、末句和尾部完整性。
3. 按真实录音语义对照文案，修正明确的错字、同音错误、无意义重复和断句；不改观点、不补造内容。
4. 生成带时间戳 SRT，随后锁定字幕正文、条数、首尾时间和母钟。
5. 建立词级定位，分别记录 `sceneStart`、`actionCue`、`textCue`、`resultCue`、`exitCue`。
6. 未锁定母钟和 SRT 前，不设计正式逐镜动作。

任何只改画面的返工都必须验证音频、字幕和时间轴指纹未变。

## 4. 语义先于画面

每镜先写唯一主命题，再拆：主语、动作、受力对象、转折、结果、观众此刻应理解什么。动画必须展示这些对象之间的关系，而不只是摆出名词。

独立生成或拆分所有需要不同时间、方向、深度或作用方式的人物、工具、路径、受力对象和结果状态。完整构图只能做美术参考或情境插画；整图缩放、平移、裁切、轻视差和呼吸不能冒充语义动画。

每个主要图层必须定义：

`进入 → 落稳 → 作用/受力 → 让位 → 收束 → 离场`

同一时刻只保留一个主语义视觉。新主层进入前，旧主层必须退出、转化或降级到不再抢焦；仍清楚可辨并干扰理解就不算退出。

详细组件、节奏、解释文字和字幕合同见 [semantic-motion-and-typography.md](references/semantic-motion-and-typography.md)。

## 5. 节奏感知预算

不要每句话都换整套画面，也不要为了“有动画”连续闪切。

- 相关语义优先放在一个稳定主构图中，用局部聚焦、状态变化和主次接管解释。
- 稳定主构图默认目标为约 2–5 秒；短于 1.5 秒的完整主构图必须在镜头合同中写明必要理由。
- 核心动作落稳后，在口播允许时保留至少约 0.8 秒可辨认状态。
- 字幕变化不等于主构图必须变化。
- 全片设计后专门审计前 15 秒和信息密集段；若观众尚未读清主体与解释就被替换，合并阶段或降低主层切换频率。

节奏优化只压缩主构图切换，不得删除核心语义动作。

## 6. 解释文字与语义容器

字幕负责原话；解释文字负责判断、分类、因果或结论；对象标签负责识别当前物件。三者不得互相复述。

核心语义动画必须有可读解释，但不是每一句口播都强制配图或卡片。解释可以是无底板大字、侧边竖排、括号批注、印章、阶梯、弧线、报刊短栏、聚焦环、局部揭示、票签或路径标识；不得全片只用一种顶部卡片。

任何气泡、票据、输入框、手机屏幕、图表、文档、按钮、选项或标签，只要承担交流或判断功能，就必须填入本地排版的有效文字。先识别容器内部可写区域，再把文字绑定到该组件的本地坐标系：文字位于容器内部、继承父组件的位置/缩放/旋转/透视和遮罩，并随父组件同步运动。禁止用漂在组件上方的独立卡片假装“已经填字”。纯装饰容器必须明确标为装饰；禁止留下让观众以为“这里应该有字”的空白语义容器。

每个承担语义的容器都要在逐镜合同中记录 `parent_layer_id`、归一化 `text_region_normalized`、内边距、最小字号、透视模式、裁切遮罩和父子运动绑定。文字内容、字重、行数和层级按容器真实比例微调；手机或图表内部的字必须看起来像界面本身，而不是后贴标签。

禁止：

- 解释文字复述字幕；
- 右上角或边角出现手机上无法阅读的小字；
- 独立解释文字无理由黏在运动物件上；语义容器内部文字反而必须绑定并跟随其父组件；
- 把本应填在手机、图表、气泡或票据内部的文字做成脱离组件的悬浮卡片；
- 为解决遮挡直接删除必要解释；
- 依赖生图模型生成可读中文；
- 在正式画面保留镜号、SceneHeader、场景说明、调试标记或内部注释。

## 7. Gate 2：先审完整方案，再生产

对定稿录音项目，Gate 1 默认内部整合；若没有真实内容冲突，不拿纯文字中断用户。第一个常规用户审核点是 Gate 2。

Gate 2 必须一次性交付全片：

- 每镜完整 TXT 合同；
- 每镜参考图或关键帧；
- 组件镜头的多阶段关键帧和独立图层计划；
- 每个语义容器的内部文字区域、父图层绑定、透视/遮罩方案，以及每个本地组件镜头的逐镜构图适配计划；
- Flow 镜头在全片中的参考图与脚本方案；
- 全片总览、节奏密度、文字职责和空白语义容器检查。

所有审核文件单层平铺，不建立一镜一个子文件夹。交付后真正停止。只有用户明确确认“整套通过 / 全部没问题”后才能生产正式动画。

Gate 2 未通过时禁止：正式合成、正式全片动画、把低清全片当审核替代品、提前拆出 Flow 操作包。

## 8. Gate 2.5：单独交付 Google Flow

Gate 2 整套通过后，只把已批准的 Flow 镜头单独整理给用户：每镜一张无字准备态参考图、一份生产级完整提示词、对应口播、目标时长和回收位置。不要夹带非 Flow 图片或旧版提示词。

用户手动生成回收后：

1. 按内容检查，不信任文件名；
2. 保留 raw 原件并记录实际镜头映射；
3. 检查首中尾、动作、人物、手部、伪文字、水印和构图漂移；
4. 移除全部源声音；
5. 统一规格但不擅自改变已批准动作、速度或时序；
6. 按动作发生帧对齐真实 `actionCue`。

Flow、本地文字、青年明亮音和配乐合同见 [flow-audio-and-composition.md](references/flow-audio-and-composition.md)。

## 9. 正式合成

- 所有动作服从绝对母钟，不按镜头平均分段。
- 核心动作最多提前关键词约 0.10–0.18 秒作准备；铺垫期只保留中性上下文。
- 解释文字按独立 `textCue` 出现，不能抢拍，也不能等动作完成后才补。
- 合成顺序固定为：识别承担语义的容器 → 把文字绑定进组件内部并完成内边距、字号、透视和遮罩 → 把容器文字与父组件组成同一视觉组 → 再逐镜放大、居中和适配整个视觉组。禁止先统一放大整片，再把文字漂浮覆盖上去。
- 资产类别分别处理：Flow 默认保持批准画幅、裁切、速度、动作和绝对时间不动；本地组件镜头相对批准基线以放大约 8%–12%为目标，逐镜允许约 4%–15%微调；整幅插画只在原边框内部轻微放大约 4%–6%。偏离 8%–12%目标必须逐镜写明原因，超出 4%–15%范围必须另获明确批准。
- 放大是逐镜“适配构图”，不是全片统一缩放。1080×1920 默认硬安全边界为 `x=72–1008, y=300–1290`，优选核心舞台为 `x=96–984, y=380–1280`；主要轴填充约 72%–90%，画面宽度占比不高于 90%，高度占比不高于 92%，水平中心偏移默认不超过 90px。数值是起始约束，不是机械目标；密集镜头可保守微调，但必须保证不裁切、不漂移、不破坏主次、不遮字幕/平台 UI，并记录例外原因。
- 本地组件集中在中部核心舞台并保证手机可读；放大后从进入、核心动作到离场连续检查组件内文字、裁切、构图、主次关系、左右安全距离和字幕避让。最终验收以“看得明白、观感舒适”为准，不能用满足缩放数字替代真实观看。
- 竖屏短视频字幕默认优先单行；禁止依赖自动换行。按最终编码实测宽度动态调整字号或重新拆分 SRT，二行字幕必须是经批准的例外。
- 字幕必须形成比背景更强的前景层级：先记录上一批准版的逐条字号/位置基线，再在不溢出的前提下确认本轮字号确实增加，整体向中心安全区上移，并通过实心字、粗描边、纸片投影或局部底衬建立稳定对比；字体气质必须与杂志插画统一。零增量、保持不动或反向避让都必须有逐条理由。
- 字幕位置逐镜避让主视觉；不得为了“向中心移动”压住人物、核心动作、结果状态或解释文字。低位 Flow 或特殊构图可在批准范围内局部回避，但必须记录偏移和原因。
- 默认加入无歌词、低存在感、语音优先的背景音乐；开头淡入、结尾淡出，人声出现时自动闪避。用户明确不要配乐时才省略。
- 先确认用户的声音档案；不得把示例项目的声音参数强加给其他品牌。用户明确要求 `muzhi_bright_youth` 时，才使用已验证的青年明亮音档案，并保持样本数、语速和总时长不变。

## 10. 返工先锁边界

任何 v2、v3、v4……返工开始前：

1. 完整保留一个明确回退版本；
2. 写 `editorial-revision-lock-vN.json`；
3. 列出唯一允许修改项、禁止修改项和必须保持的文件/音视频指纹；
4. 用户说“Flow 不要动”“只放大本地动画”等即转成哈希锁定；
5. 返工后逐项比对，任何禁改项漂移都判失败。

不得覆盖上一验收版本。版本、锁定、清理和回退合同见 [revision-qa-and-closure.md](references/revision-qa-and-closure.md)。

## 11. Gate 3 与最终质检

渲染 1080×1920、30fps 正式母版，除非项目另有批准规格。Gate 3 前必须完成：

- 类型检查、规格探测、完整解码零错误；

- 锁定音频、字幕、时间轴、Flow 和配乐指纹；

## 11.5 Gate 3.5：发布包，不是发布

用户确认成片后，创建单层发布包：不重编码的正式母版、三平台共用 PNG/JPG 封面、标题 TXT、简介与恰好五个话题 TXT、置顶评论 TXT、发布前检查清单 TXT、版本与 SHA-256 TXT、`gate35-release-manifest.json`。封面文字必须本地精确排版并位于中心安全区；发布母版哈希必须与 Gate 3 一致。

Gate 3.5 状态只能写 `release_ready_not_published`。登录、上传、定时和发布属于 Gate 4，仍需单独授权。模板与验收字段见 [production-enforcement-and-release.md](references/production-enforcement-and-release.md)。

## 12. 收束、清理与发布闭环

成片通过后：

- 保留当前最终版、明确回退版、源素材、批准资产、正式音频、最终 QA 和必要工程源码；
- 只删除用户已授权且可再生成的中间产物，先列清单、核对绝对路径和哈希，再执行并记录释放空间；
- 成片验收不等于发布授权；登录、上传、发布必须单独获得授权；
- 用户确认平台已发布后，登记每个平台的原生作品 ID、链接、发布时间和工作台记录；
- 启动并记录 24h、72h、7d 数据节点；没有公开链接的平台使用原生 ID 跟踪，不伪造链接；
- 工作区模式同步项目状态、工作台、工作人员进度页、知识库经验和当前会话交接；独立模式只更新当前项目合同、决策与交接，不假设存在私有工作台或知识库。

已验证案例、四轮返工根因和最终 QA 基线见 [validated-case-and-qa.md](references/validated-case-and-qa.md)。

## 一票否决

任一项出现即不得宣称本阶段完成：

- 未经 Gate 2 整套批准即开始正式动画或拆出 Flow 操作包；
- 用整图轻动冒充语义动画；
- 主构图闪切到观众无法看清，或短阶段无例外记录；
- 空白气泡、票据、输入框、选择卡等语义容器；
- 解释文字复述字幕、不可读小字、全片同一种卡片；
- 新主层接管后旧主层仍停留抢焦；
- 动作、解释文字和口播关键词错位；
- 生成文字、乱码、水印、Logo、二维码或 Flow 源声音进入正式片；
- 正式画面出现镜号、场景说明、调试标记；
- 用户要求青年明亮音但仍使用未处理原声，或处理造成母钟漂移；
- 无明确理由缺少背景音乐，或音乐压住口播；
- 返工修改了锁定的 Flow、音频、字幕或时间轴；
- 字幕自动换行、断词、裁切或贴边；
- 本地主要元素仍小而分散、未经逐镜检查就整体等比放大，或整幅插画放大越过原边框；
- 字幕层级低于背景、字号不舒适、没有向中心安全区优化，或遮挡主视觉/解释文字；
- 未完整观看、未做桌面哈希核对就交付；
- 正式生产仍使用旧 schema，或只用布尔勾选而没有真实证据文件；
- 旁链后 BGM 全片或任一关键分段低到实质不可感知，只因总响度合格就宣称声音通过；
- 把“成片通过”写成“已发布”，或未经授权代替用户发布。
