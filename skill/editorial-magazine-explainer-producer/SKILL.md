# Editorial Magazine Explainer Producer

面向教育培训赛道的知识口播视频制作 Skill。把口播中的对象、数字、步骤、因果和结论转成稳定可读的杂志插画语义镜头，不按字幕逐句机械配图。

把本 Skill 当成该产线的执行控制器，而不是建议清单。任何硬 Gate、锁定项或一票否决未满足时，停止推进并说明缺口；不得用“先做出来再说”绕过。

固定规程优先级不可颠倒：`不可变生产核心 → 项目风格 → 用户新增加法要求 → 本轮返工范围`。新增风格或单条反馈只能锦上添花，不得削弱母钟、Gate 2 真暂停、语义动画、图层退出、字幕可读、语音优先配乐、证据 QA 和发布另授权。

工作区模式可继续使用正式产线与样式：

- `<OPENMONTAGE_ROOT>\pipeline_defs\editorial-magazine-explainer.yaml`
- `<OPENMONTAGE_ROOT>\styles\editorial-magazine-explainer-v2.yaml`

本产线独立于 `$vox-collage-producer`。允许在`design.md`统一画风下使用VOX式纸艺贴纸、剪报和分层MG作为B-roll动作语法，但项目仍属于杂志插画产线；不得自动改走独立VOX工作流，也不得退回通用动效模板。

独立模式不要求存在 OpenMontage；使用本 Skill 自带的合同、参考资料和校验器。

## 运行时瘦身协议（每个项目必须执行）

完整 Skill 是生产标准，不是每一轮都要重新抄进上下文的施工记录。正式开工后，从 `assets/templates/editorial-job-card.template.md` 创建 `<PROJECT_ROOT>\artifacts\editorial-job-card.md`。Gate 2A再从`assets/templates/design.template.md`创建项目根目录唯一`design.md`，并用`artifacts/design-lock.json`锁定其哈希与风格参考图。以后每轮先读施工单；任何视觉生产再读`design.md`，然后按当前 Gate 只读一个相关参考文件和本轮真实产物。

- 重点片且已选定杂志插画形式，才进入本 Skill；快速片、普通露脸、评论回应或白板短讲不得为了显得精致而强行套完整产线。
- 施工单只保留：本条目标、真实事实源、当前 Gate、已批准锁定项、本轮允许修改项、唯一下一步、必须读取的一个参考文件、上次校验结果和待用户决定事项。
- `design.md`只保留：获批风格板、人物/场景/色板/材质/构图、保留项与只改项、语义群B-roll地图、供应商边界、核心文字嵌套和当前视觉Gate。它是项目唯一视觉入口；其他提示词或部门文档不得另起画风。
- 不因切换会话重复读取整库、全部决策日志、全部案例和所有参考文件；只有核实冲突、返工边界或校验失败时，才按证据路径追读。
- Gate 交付给用户只说：现在看到什么、哪几项已经锁定、这轮请看什么、通过后会发生什么。完整机器字段留在项目 `artifacts/`，不让用户读工程流水。
- 同一故障第二次出现时，不再追加一篇复盘；必须把它变成模板字段、校验规则或预渲染检查。
- 每轮结束必须更新施工单；下一位工作人员只凭施工单、当前合同和对应 Gate 产物即可续做。

具体路由、阶段最小读取和重复故障预检见 [runtime-production-playbook.md](references/runtime-production-playbook.md)。`design.md → 语义B-roll → 自有生图参考帧 → 图生视频 → 原生事实组件`的固定流程见 [design-board-and-broll-pipeline.md](references/design-board-and-broll-pipeline.md)。

导演理解、可理解画面段、完整故事板、有声动态分镜、真实材料/来源图表与各类动画的选择规则，统一见 [director-storyboard-and-visual-routing.md](references/director-storyboard-and-visual-routing.md)。它是任何正式生图、付费图生视频和完整正式生产时间线之前的硬Gate；低成本全片有声动态分镜本身是必经审核物，不算违规提前搭正式时间线。

## 正式生产计时与当天交付目标

只有以下三项全部锁定后，正式制作时钟才开始：

1. 定稿文案；
2. 支撑口播判断的证据包；
3. 最终口播音频。

从此刻起，正常项目以当天完成正式母版、三平台封面和发布包为目标。阶段不设固定分钟配额，不得为了赶时间跳过Gate或降低质量；某条生成路线连续失败时应及时换供应商、改成本地原生动画或重写镜头，不允许无限重试。

镜头总数、章节总数和单段时长均不预设。导演按口播语义、观众阅读时间、动画解释动作和供应商时长能力划分**可理解画面段**。相关口播可以在同一稳定构图内连续推进；图生视频常见单条上限约10秒，预计素材短于口播时必须提前设计首尾连续镜头、MG续接或替代路线，禁止明显降速、尾帧停死、无意义循环或静态闪图补时长。

## 0. 执行授权

若项目目录或其父级存在 `AGENTS.md`，先读取并遵守。无论使用哪种模式，都先渐进澄清、完整复述目标、解释执行步骤与审核方式，等待用户明确回复“同意 / 开始 / 执行”。授权前不读取资产、不调用生成、不修改、不渲染、不发布。

只有执行范围、内容、审美、声音、供应商、费用、时长、发布权限都达到至少 95% 清晰度后才提交执行方案。每次只问一个问题。已授权范围内正常推进；发生实质变化时重新确认。

## 1. 启动必读与续做路由

获得执行授权后，按模式读取：

1. **工作区模式：**只读工作区入口、当前工作总览、Codex公司任务看板、当前视频业务入口和本项目施工单；决策日志、每日总结和长篇产线文档只在核实冲突时按需读取；
2. **独立模式：**只读本 Skill、项目施工单、用户提供的品牌规范和当前 Gate 所需的口播、SRT、文案或资产；不得寻找或假设牧之远见私有文件；
3. 新项目首次建立基线时读取最近一条可访问、已获授权的同产线项目最终 QA；没有案例时读取 `references/validated-case-and-qa.md`。续做时不得每轮重读全部案例；
4. 续做项目只读施工单、当前合同、最新审核状态、本轮允许修改的资产和对应 Gate 的一个参考文件。

不得仅凭当前对话重建已批准的镜头、Flow、字幕、音频或版式。续做时从第一个未完成 Gate 开始。

入口路由：

- **真实录音＋已确认文案：**真实录音是唯一事实源和母钟；文案只用于核对语义、错字、同音词和断句。
- **真实录音＋SRT：**SRT 是字幕正文基准；词级对齐只服务动画锚点，不擅改字幕措辞。
- **只有定稿文案：**只做临时规划时码；录音到位后必须重建字幕与动作锚点。
- **只有想法：**先调用 `$video-spec-builder` 完成导演式澄清和口播定稿，再返回本 Skill。
- **既有项目：**先检查批准版本、锁定指纹、当前 Gate 和待办；不重复生产已通过内容。

### 产线、转写与公司 Gate 归属

- 先识别正式产线，再选工具；插件可用不等于自动切换产线。按“事实源、精度、可重复、可编辑、成本、当前产线兼容”依次选择，不因新插件更酷而替换已验证工具。
- **工作区模式 Gate 0/1：**真实录音是母钟，本地 `faster-whisper large-v3` 是正式 ASR 默认；一次产出逐词时间戳、segments、SRT 和 TXT，并按定稿文案做人工纠错后锁定。ChatCut 在自己的编辑器项目可作主转写；在 OpenMontage 正式项目只作辅助或第二路，不替代正式 SRT，除非牧之明确批准切换。
- 同一音频默认只跑一次正式 ASR。第二路只能用于专业名词冲突、低置信度、词级时码交叉校验或复用既有结果，必须在施工单写明目的；禁止无意义重复转写。
- **独立模式：**可选最合适的可用 ASR，但须在合同记录 provider、模型、词级能力与正式事实源；不得强行要求 OpenMontage 私有工具。
- **工作区公司 Gate 接力：**00｜牧之总控台只做路由、任务包和 Gate 裁决；03｜视频制作部是唯一生产负责人、唯一导演和唯一时间线 owner；02只守定稿文案和真实口播边界；05负责证据与来源；06复核导演故事板、文字/容器、风格、封面和手机观感；07负责工具路由、时长覆盖、校验和重复劳动防护。牧之只看四份真正有决策价值的包：①人话版导演理解＋完整视觉故事板，②全片有声动态分镜＋最难段真实完成度样片，③完整低清粗剪，④最终母版与发布包。部门不得在总控已取得本轮授权后层层重复询问用户。
- 每个产物只能有一个 owner；单条片最多三种角色：导演/生产 owner、时间线 owner、技术或资产助手。导演与时间线 owner 可由同一人兼任。第二工具或第二部门必须写清交叉验证目的，不得平行重做视觉方向。

详细启动、交付物和 Gate 合同见 [workflow-and-review-gates.md](references/workflow-and-review-gates.md)。

### 黄金基准与真实动态样片

重点片不再从空白审美出发。工作区模式默认以已经验收的《双非考研，别再问“哪所学校好考”了》V3 作为唯一杂志插画黄金基准；锁定其约 90% 的画风、构图秩序、动作语法、字幕层级、声音关系和品牌收尾，只允许约 10% 因当前选题产生的必要升级。独立模式必须由用户提供一条已批准母版作为本项目基准；没有基准时先做方向样片，不得把未验收案例写成黄金标准。

完整规则见 [golden-baseline-and-motion-pilot.md](references/golden-baseline-and-motion-pilot.md)。任何重点片必须先做 15—20 秒真实动态样片，且必须使用本条片的真实口播、真实字幕、真实画面资产、真实动作和真实声音关系。优先选择最难的语义段，而不是最容易做漂亮的一段。样片阶段默认最多 10 次图像生成、2 次 Flow 测试；没有用户明确批准，不得放行全片生图、全片 Flow、全片动画或正式合成。

导演简报通过后、任何正式参考图生成前，必须建立并批准项目根目录`design.md`。自有生图负责根据`design.md`决定人物、场景、构图、光影与画风；WAN、ChatCut、MiniMax、Google Flow或未来图生视频供应商只能接收已经批准的首尾参考图负责动作，不得只凭纯文字重新定义风格。运行`validate_design_lock.py --require-approved`失败时，禁止生图扩量和图生视频提交。

以下任一观感出现即判方向失败并停止扩量：**像 PPT、像廉价 AI、画风混乱、动画僵硬**。机器检查只能证明文件能播，不能推翻这四项人工否决。

## 2. 建立机器可检验的项目合同

在项目 `artifacts/` 下从模板创建：

- `editorial-job-card.md`：运行时短施工单；每轮更新，不替代机器合同；
- `director-storyboard.json`：生产计时、导演理解、全片可理解画面段、语义表现路由、证据/来源脚注、完整有声动态分镜、每片新BGM和06/07双签；
- `editorial-project-contract.json`：母钟、字幕、镜头、Gate、Flow 和声音合同；
- `editorial-gate2-manifest.json`：逐镜合同/TXT/关键帧、全片总览、语义容器原生文字与构图适配审计的路径、真实哈希及整套批准证据；
- 每次返工创建 `editorial-revision-lock-vN.json`：只准改什么、绝对不能改什么、回退版本和锁定指纹；
- Gate 3 创建 `editorial-qa-manifest-vN.json`：技术、声音、视觉、全片观看和桌面哈希结果。

模板位于本 Skill 的 `assets/templates/`。逐镜模板与项目合同中的 `shots[]` 使用同一结构。正式推进前运行：

```powershell
python "<SKILL_ROOT>\scripts\validate_editorial_project.py" --project-contract <项目合同>
```

逐镜和 Gate 2 分别使用 `--shot-contract`、`--gate2-manifest`；返工或 Gate 3 追加 `--revision-lock`、`--qa-manifest`。正式 Gate 校验默认读取真实文件并重算哈希；`--skip-file-verification` 只供草拟结构，永远不能用来解锁生产。校验失败即 Gate 关闭。

新项目或任何返工还必须从 `production-enforcement.template.json` 创建 `production-enforcement.json`，并运行：

```powershell
python "<SKILL_ROOT>\scripts\validate_production_enforcement.py" --manifest <PROJECT_ROOT>\artifacts\production-enforcement.json
```

正式生产只接受当前模板声明的schema；旧schema只供历史读取，不能解锁新生产。四层优先级、黄金基准、导演故事板、动态分镜、真实样片、语义/时序/生命周期/布局、完整粗剪、三轨声音和证据文件见 [production-enforcement-and-release.md](references/production-enforcement-and-release.md)。

导演计划完成后必须运行两次：

```powershell
python "<SKILL_ROOT>\scripts\validate_director_storyboard.py" --contract <PROJECT_ROOT>\artifacts\director-storyboard.json --stage plan
python "<SKILL_ROOT>\scripts\validate_director_storyboard.py" --contract <PROJECT_ROOT>\artifacts\director-storyboard.json --stage batch
```

`plan`检查完整口播覆盖、无固定凑镜头、表现形式选择、证据来源、图生视频时长计划和全新BGM简报；`batch`额外要求视觉故事板、完整有声动态分镜、BGM文件/哈希、用户批准与06/07双签。第二次未通过，不得批量生图、图生视频或搭完整正式时间线。

图生视频和其他动态素材回收后、进入完整合成前，还必须按真实文件探测时长：

```powershell
python "<SKILL_ROOT>\scripts\validate_dynamic_asset_duration.py" --manifest <PROJECT_ROOT>\artifacts\dynamic-asset-duration-records.json
```

该Gate直接读取素材文件和SHA-256，用FFprobe核对真实视频流、时长、播放速度和续接覆盖，并抽样比较帧周期识别“仍在运动但整段重复”的循环；明显慢放、尾帧停死、无意义循环、静态闪图或短素材硬撑长口播均关闭合成Gate。

## 3. 母钟与字幕先锁定

1. 安全复制原始录音、定稿文案、SRT 和用户素材；保留原件。
2. 复核录音时长、采样率、声道、末句和尾部完整性。
3. 按真实录音语义对照文案，修正明确的错字、同音错误、无意义重复和断句；不改观点、不补造内容。
4. 生成带时间戳 SRT，随后锁定字幕正文、条数、首尾时间和母钟。
5. 建立词级定位，分别记录 `sceneStart`、`actionCue`、`textCue`、`resultCue`、`exitCue`。
6. 未锁定母钟和 SRT 前，不设计正式逐镜动作。

任何只改画面的返工都必须验证音频、字幕和时间轴指纹未变。

## 4. 语义先于画面

每镜先写唯一主命题，再拆：主语、动作、受力对象、转折、结果、观众此刻应理解什么。动画必须展示这些对象之间的关系，而不只是摆出名词。

独立生成或拆分所有需要不同时间、方向、深度或作用方式的人物、工具、路径、受力对象和结果状态。完整构图只能做美术参考或情境插画；整图缩放、平移、裁切、轻视差和呼吸不能冒充语义动画。

每个主要图层必须定义：

`进入 → 落稳 → 作用/受力 → 让位 → 收束 → 离场`

同一时刻只保留一个主语义视觉。新主层进入前，旧主层必须退出、转化或降级到不再抢焦；仍清楚可辨并干扰理解就不算退出。

每个可理解画面段还必须先选择正式表现路线：`image_to_video / native_mg / official_evidence / sourced_chart / vox_layered_broll / real_media / hybrid`。准确数字、学校名、表格、名单和政策正文不得走纯图生视频；人物、情境、笑点、空间和非数据型抽象语义优先图生视频；方法/路径优先VOX纸艺图层；官方材料优先真实网页/PDF/截图；已核验数据可以重画图表，但画面下方必须标出可读来源。

详细路由与故事板合同见 [director-storyboard-and-visual-routing.md](references/director-storyboard-and-visual-routing.md)；组件、节奏、解释文字和字幕合同见 [semantic-motion-and-typography.md](references/semantic-motion-and-typography.md)。

## 5. 节奏与理解时间

不要每句话都换整套画面，也不要为了“有动画”连续闪切。

- 相关语义优先放在一个稳定主构图中，用局部聚焦、数据拆分、状态变化和主次接管解释；内部持续有有效动作时，不为追求镜头数强行切走。
- 不规定主构图必须持续几秒；时长服从完整口播和观众理解。短于1.5秒的完整主构图必须说明必要理由，较长画面段必须有连续解释动作，不能只停一张图。
- 核心动作落稳后，在口播允许时保留至少约0.8秒可辨认状态；名单、表格、来源和核心数字还要按真实阅读量增加停留。
- 字幕变化不等于主构图必须变化。
- 全片设计后专门审计前 15 秒和信息密集段；若观众尚未读清主体与解释就被替换，合并阶段或降低主层切换频率。

节奏优化只压缩主构图切换，不得删除核心语义动作。

## 6. 解释文字与语义容器

字幕负责原话；解释文字负责判断、分类、因果或结论；对象标签负责识别当前物件。三者不得互相复述。

实现时固定区分`InsetText / Callout / BrandText`：组件内部字必须使用父组件本地坐标；独立解释默认使用暖纸实体底，不在人物、视频、浅纸或动态明暗背景上裸浮白字；品牌结尾出现相同slogan时，普通字幕必须退出，不能显示两遍。

核心语义动画必须有可读解释，但不是每一句口播都强制配图或卡片。解释可以是无底板大字、侧边竖排、括号批注、印章、阶梯、弧线、报刊短栏、聚焦环、局部揭示、票签或路径标识；不得全片只用一种顶部卡片。

任何气泡、票据、输入框、手机屏幕、图表、文档、按钮、选项或标签，只要承担交流或判断功能，就必须填入本地排版的有效文字。先识别容器内部可写区域，再把文字绑定到该组件的本地坐标系：文字位于容器内部、继承父组件的位置/缩放/旋转/透视和遮罩，并随父组件同步运动。禁止用漂在组件上方的独立卡片假装“已经填字”。纯装饰容器必须明确标为装饰；禁止留下让观众以为“这里应该有字”的空白语义容器。

“位于容器内部”必须按文字真实包围盒验收，不以锚点坐标落在容器里代替：标题、正文和标签的完整字形必须进入真实可写区并留出内边距，不能压在边框、箭头终点、路径交叉点或两层交界处；标题不得覆盖底图中的人物、图标、路标和箭头。发现空间归属不清时先重新划分可写区，再放大字号和调整坐标，不能只加纹理或阴影假装已经嵌套。

每个承担语义的容器都要在逐镜合同中记录 `parent_layer_id`、归一化 `text_region_normalized`、内边距、最小字号、透视模式、裁切遮罩和父子运动绑定。文字内容、字重、行数和层级按容器真实比例微调；手机或图表内部的字必须看起来像界面本身，而不是后贴标签。

生图得到的票据、纸张或卡片只允许在“内部信息槽边界稳定、透视可匹配、最小字号成立”时继续作为文字容器。第一次适配失败先校正真实可写区域；同一容器连续两轮仍出现文字错位、字号与容器不成比例、边框穿字或父子运动脱节，立即改用本地原生组件重构整张卡，不得继续移动全片绝对坐标碰运气。原生组件必须把底板、边框、标题、正文、状态、印章和动画封装为同一个父组，整体进入、缩放和退出。

禁止：

- 解释文字复述字幕；
- 右上角或边角出现手机上无法阅读的小字；
- 独立解释文字无理由黏在运动物件上；语义容器内部文字反而必须绑定并跟随其父组件；
- 把本应填在手机、图表、气泡或票据内部的文字做成脱离组件的悬浮卡片；
- 同一生成容器已经连续两轮适配失败，仍继续微调绝对坐标而不切换原生组件；
- 为解决遮挡直接删除必要解释；
- 依赖生图模型生成可读中文；
- 在正式画面保留镜号、SceneHeader、场景说明、调试标记或内部注释。
- 用突兀纯黑多边形遮生成伪UI；优先裁切、降级或使用透视/材质一致的完整本地组件替换。

## 7. Gate 2：导演理解、完整故事板、动态分镜与真样片

对定稿录音项目，Gate 1 默认内部整合；若没有真实内容冲突，不拿纯文字中断用户。重点片先交人话版导演理解：核心承诺、观众问题、前3秒/前10秒价值、答案/证据/案例/方法/笑点分工、表现形式和全片动作接力。章节和镜头数量不得预设。

导演理解通过后，先建立项目唯一`design.md`并锁定2—4张获批风格参考图，再完成整条口播的导演故事板。每个可理解画面段必须包含准确口播时码、观众问题与结论、表现路线、首帧/变化/落稳/退出、屏幕文字、证据来源、供应商时长与前后接力。随后先拼从头到尾的有声动态分镜，验证所有有口播都有画面、观众来得及读、动画不会提前结束、转场不生硬、本条新BGM与人声关系成立。

完整故事板和有声动态分镜获批后，才用最难15—20秒制作真实完成度样片。只允许用自有生图能力生产样片所需的首帧、转折帧和尾帧；参考图获用户批准后，图生视频供应商才可把这些画面动起来。样片必须同时验证：

- 杂志插画画风是否与黄金基准同源；
- 语义是否靠独立组件动作讲清，而不是整图轻动；
- 文字是否真正长在卡片、手机、图表或票据里；
- 字幕、解释文字、画面和人声是否抢焦；
- 主构图是否留得住，动作是否自然，声音是否完整；
- 是否出现“像 PPT、像廉价 AI、画风混乱、动画僵硬”中的任何一项。

样片未通过时只改方向样片，不批量扩展。若问题来自画风漂移，先回到`design.md`或自有生图参考帧，不得直接要求图生视频供应商“再试一种风格”。连续两轮仍命中同一方向性否决时，停止当前视觉路线并回到导演简报，不再用增加素材数量掩盖问题。样片只有在保存批准人、原话、时间和真实文件哈希后才算通过。

样片通过后，才按已经批准的完整故事板一次性生产全片参考图、组件、真实材料、图生视频和来源图表。不得在样片通过后重新发明镜头，或用供应商生成得漂亮为理由把素材换到不对应的口播。静态全片总览不能代替有声动态分镜或真实动态样片。

样片未通过时禁止：全片生图、全片 Flow、全片正式动画、正式合成、拆出完整 Flow 操作包。详细闸门见 [workflow-and-review-gates.md](references/workflow-and-review-gates.md)。

## 8. Gate 2.5：样片通过后生产有机动态镜头

“Flow镜头”是有机动作镜头类别，不等于必须使用Google Flow。真实动态样片明确通过后，为每个已批准的有机动作画面段准备：由`design.md`派生且已经批准的无字首帧/尾帧、生产级完整提示词、对应口播、目标时长、动作锚点、结束状态、续接方案和回收位置。供应商只负责人物、情境、笑点、空间和非数据动作，不拥有画风决定权，也不承担准确中文、数字、表格和政策正文。

工作区存在经过用户批准、可自动提交的图生视频供应商时，由视频制作部自动完成提交、任务ID落盘、轮询、下载、验收和回填，默认不再要求用户手动生成。当前牧之远见工作区优先使用MiniMax直连的`MiniMax-Hailuo-2.3`；密钥只能保存在工作区外的本机加密秘密区，不得进入项目、Skill、知识库、日志或Git。每个任务必须记录首帧/提示词/输出哈希、模型、分辨率、时长、费用来源、任务ID、状态、下载位置和是否采用，失败或本地超时先续查原任务，禁止直接重复提交扣费。

自动供应商不可用、质量连续失败或用户明确要求Google Flow时，才退回手动生成包。不要夹带非动态参考图或旧版提示词。

生成结果回收后：

1. 按内容检查，不信任文件名；
2. 保留 raw 原件并记录实际镜头映射；
3. 检查首中尾、动作、人物、手部、伪文字、水印和构图漂移；
4. 移除全部源声音；
5. 统一规格但不擅自改变已批准动作、速度或时序；
6. 按动作发生帧对齐真实 `actionCue`。
7. 从`dynamic-asset-duration-records.template.json`建立真实时长记录并通过`validate_dynamic_asset_duration.py`；未通过不得进入完整合成。

能用固定透视遮罩、本地准确文字或局部裁切修复的伪UI/伪字，可以保留人物与核心动作继续使用；人物、手部、画风或核心动作损坏才整条重生。改变素材用途时必须与真实口播一致并记录，例如把模型误生成的扔书动作改作口播中的夸张反例，不能伪装成原计划已实现。

Flow、本地文字、青年明亮音和配乐合同见 [flow-audio-and-composition.md](references/flow-audio-and-composition.md)。

## 9. 正式合成

- 所有动作服从绝对母钟，不按镜头平均分段。
- 核心动作最多提前关键词约 0.10–0.18 秒作准备；铺垫期只保留中性上下文。
- 解释文字按独立 `textCue` 出现，不能抢拍，也不能等动作完成后才补。
- 合成顺序固定为：识别承担语义的容器 → 把文字绑定进组件内部并完成内边距、字号、透视和遮罩 → 把容器文字与父组件组成同一视觉组 → 再逐镜放大、居中和适配整个视觉组。禁止先统一放大整片，再把文字漂浮覆盖上去。
- 资产类别分别处理：Flow 默认保持批准画幅、裁切、速度、动作和绝对时间不动；本地组件镜头相对批准基线以放大约 8%–12%为目标，逐镜允许约 4%–15%微调；整幅插画只在原边框内部轻微放大约 4%–6%。偏离 8%–12%目标必须逐镜写明原因，超出 4%–15%范围必须另获明确批准。
- 放大是逐镜“适配构图”，不是全片统一缩放。1080×1920 默认硬安全边界为 `x=72–1008, y=300–1290`，优选核心舞台为 `x=96–984, y=380–1280`；主要轴填充约 72%–90%，画面宽度占比不高于 90%，高度占比不高于 92%，水平中心偏移默认不超过 90px。数值是起始约束，不是机械目标；密集镜头可保守微调，但必须保证不裁切、不漂移、不破坏主次、不遮字幕/平台 UI，并记录例外原因。
- 本地组件集中在中部核心舞台并保证手机可读；放大后从进入、核心动作到离场连续检查组件内文字、裁切、构图、主次关系、左右安全距离和字幕避让。最终验收以“看得明白、观感舒适”为准，不能用满足缩放数字替代真实观看。
- 竖屏短视频字幕默认优先单行；禁止依赖自动换行。按最终编码实测宽度动态调整字号或重新拆分 SRT，二行字幕必须是经批准的例外。
- 字幕必须形成比背景更强的前景层级：先记录上一批准版的逐条字号/位置基线，再在不溢出的前提下确认本轮字号确实增加，整体向中心安全区上移，并通过实心字、粗描边、纸片投影或局部底衬建立稳定对比；字体气质必须与杂志插画统一。零增量、保持不动或反向避让都必须有逐条理由。
- 字幕位置逐镜避让主视觉；不得为了“向中心移动”压住人物、核心动作、结果状态或解释文字。低位 Flow 或特殊构图可在批准范围内局部回避，但必须记录偏移和原因。
- 每条正式片必须根据本条主题重新制作或重新取得一首无歌词、低存在感、语音优先的背景音乐；默认调用`$music`形成新曲。开头淡入、结尾淡出，人声出现时自动闪避。必须检查全部已通过/已发布项目的BGM登记册，不只比较上一条；相同生成任务、曲目身份、音频指纹或实质同曲改码版本均判复用失败，只有用户明确指定沿用并保存原话与时间时才例外。用户明确不要配乐时才省略。
- 音乐简报必须写清主题、情绪、能量走势、乐器/质感、语音让位方式和来源。正式资产记录供应商或许可来源、`canonical_track_id`、原始文件SHA-256、音频指纹、全项目登记册检查、旁链后分轨和最终混音。
- 先确认用户的声音档案；不得把示例项目的声音参数强加给其他品牌。用户明确要求 `muzhi_bright_youth` 时，才使用已验证的青年明亮音档案，并保持样本数、语速和总时长不变。

## 10. 返工先锁边界

任何 v2、v3、v4……返工开始前：

1. 完整保留一个明确回退版本；
2. 写 `editorial-revision-lock-vN.json`；
3. 列出唯一允许修改项、禁止修改项和必须保持的文件/音视频指纹；
4. 用户说“Flow 不要动”“只放大本地动画”等即转成哈希锁定；
5. 返工后逐项比对，任何禁改项漂移都判失败。

不得覆盖上一验收版本。版本、锁定、清理和回退合同见 [revision-qa-and-closure.md](references/revision-qa-and-closure.md)。

## 11. Gate 3 与最终质检

渲染 1080×1920、30fps 正式母版，除非项目另有批准规格。Gate 3 前必须完成：

- 类型检查、规格探测、完整解码零错误；
- 黑帧、异常静音、响度、响度范围、真峰值；
- 锁定音频、字幕、时间轴、Flow 和配乐指纹；
- 所有组件语义阶段；
- 所有 Flow 和整幅插画；
- 资产类别放大与中部集中审计：Flow 锁定不变、本地组件逐镜放大、整幅插画边框内放大、裁切和构图破坏均为 0；
- 语义容器原生文字审计：父图层绑定、组件内坐标、透视、遮罩、溢出、可读性与父子运动同步；漂浮覆盖、脱节、出框和不同步均为 0；
- 自适应构图审计：每个本地组件镜头都有基线比例、最终比例、最终包围盒、安全边界、主轴填充、中心偏移和人工舒适度记录；裁切、漂移、主视觉遮挡和不舒适密度均为 0；
- 最长字幕单行边界；
- 字幕视觉层级审计：最终字号、中心方向位移、前景/背景对比策略、风格匹配、溢出、安全区违规和主视觉遮挡；
- 空白语义容器、小字、生产标记、遮挡和旧层滞留；
- 所有发生过修改的连续关键区段；
- 从头到尾完整观看一次。

复制而不是移动审核产物到：

`<DESKTOP_REVIEW_ROOT>`

使用清晰中文版本名；核对工程母版与桌面副本 SHA-256 一致。Gate 3 交付后停止等待用户确认。

## 11.5 Gate 3.5：发布包，不是发布

用户确认成片后，创建单层发布包：不重编码的正式母版、三平台共用 PNG/JPG 封面、标题 TXT、简介与恰好五个话题 TXT、置顶评论 TXT、发布前检查清单 TXT、版本与 SHA-256 TXT、`gate35-release-manifest.json`。封面文字必须本地精确排版并位于中心安全区；发布母版哈希必须与 Gate 3 一致。

发布包必须检查用户所处阶段：视频、简介和置顶评论负责“领取前”的关注/留言；已经发给学生的PDF、表格或资料负责“领取后”的使用说明、品牌水印、公开账号、网站和经批准的联系方式，不得再次要求“评论领取已经拿到的资料”。视频画面禁止二维码；经批准私发的资料可以使用官网微信二维码。

Gate 3.5 状态只能写 `release_ready_not_published`。登录、上传、定时和发布属于 Gate 4，仍需单独授权。模板与验收字段见 [production-enforcement-and-release.md](references/production-enforcement-and-release.md)。

## 12. 收束、清理与发布闭环

成片通过后：

- 保留当前最终版、明确回退版、源素材、批准资产、正式音频、最终 QA 和必要工程源码；
- 只删除用户已授权且可再生成的中间产物，先列清单、核对绝对路径和哈希，再执行并记录释放空间；
- 成片验收不等于发布授权；登录、上传、发布必须单独获得授权；
- 用户确认平台已发布后，登记每个平台的原生作品 ID、链接、发布时间和工作台记录；
- 启动并记录 24h、72h、7d 数据节点；没有公开链接的平台使用原生 ID 跟踪，不伪造链接；
- 工作区模式同步项目状态、工作台、工作人员进度页、知识库经验和当前会话交接；独立模式只更新当前项目合同、决策与交接，不假设存在私有工作台或知识库。

已验证案例、四轮返工根因和最终 QA 基线见 [validated-case-and-qa.md](references/validated-case-and-qa.md)。

## 一票否决

任一项出现即不得宣称本阶段完成：

- 未经15—20秒真实动态样片批准即开始批量生图、批量Flow、全片动画或正式合成；
- 未完成人话版导演理解、完整故事板和全片有声动态分镜，或任一项未获用户批准即批量生产；
- 预设固定章节/镜头数量、为凑数碎切，或故事板没有覆盖完整母钟；
- 可理解画面段没有明确表现路线、观众结论、动画动作、阅读停留和前后接力；
- 准确学校名、数字、表格、名单或政策正文交给图生视频直接生成；
- 官方材料没有原始来源，或自制图表没有可读来源脚注与项目证据；
- 官方材料直接全屏硬贴浏览器/PDF/UI，没有经过`design.md`统一证据载体和转场；
- 空纸、纯色或无语义背景只剩唯一大字和字幕，形成普通PPT页或连续轮播；
- 图生视频预计时长短于对应口播却没有续接方案，或使用明显慢放、尾帧停死、无意义循环和静态闪图补时长；
- 单条图生视频连续使用超过10.0秒且没有用户针对该镜头的明确例外批准；
- 项目缺少已批准并通过哈希校验的`design.md`，或生图/图生视频没有引用锁定风格板；
- 只给图生视频供应商纯文字，让它从空白重新决定人物、场景和画风；
- 未经完整低清粗剪批准即渲染正式母版；
- 画面像PPT、像廉价AI、画风混乱或动画僵硬，却用机器QA合格继续推进；
- 人物、视频或浅色纸张上出现无稳定实体底的裸白解释字；
- 组件文字使用全片绝对坐标假装嵌入，或卡片缩小后核心字低于手机舒适阅读；
- 品牌slogan与普通字幕同时重复显示；
- 用整图轻动冒充语义动画；
- 主构图闪切到观众无法看清，或短阶段无例外记录；
- 空白气泡、票据、输入框、选择卡等语义容器；
- 解释文字复述字幕、不可读小字、全片同一种卡片；
- 新主层接管后旧主层仍停留抢焦；
- 动作、解释文字和口播关键词错位；
- 生成文字、乱码、水印、Logo、二维码或 Flow 源声音进入正式片；
- 正式画面出现镜号、场景说明、调试标记；
- 用户要求青年明亮音但仍使用未处理原声，或处理造成母钟漂移；
- 无明确理由缺少背景音乐，或音乐压住口播；
- 复用任一历史项目BGM，或本条BGM没有音乐简报、来源、曲目身份、音频指纹、文件哈希和全项目登记册检查；
- 返工修改了锁定的 Flow、音频、字幕或时间轴；
- 字幕自动换行、断词、裁切或贴边；
- 本地主要元素仍小而分散、未经逐镜检查就整体等比放大，或整幅插画放大越过原边框；
- 字幕层级低于背景、字号不舒适、没有向中心安全区优化，或遮挡主视觉/解释文字；
- 未完整观看、未做桌面哈希核对就交付；
- 正式生产仍使用旧 schema，或只用布尔勾选而没有真实证据文件；
- 旁链后 BGM 全片或任一关键分段低到实质不可感知，只因总响度合格就宣称声音通过；
- 把“成片通过”写成“已发布”，或未经授权代替用户发布。
- 已经交付给学生的资料仍保留“评论区留言领取本资料”等领取前话术。
